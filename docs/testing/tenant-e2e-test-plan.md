# 多租户端到端测试规则（桌面操作执行）

> 执行者：Codex，用桌面操作（浏览器界面）逐条执行，每条保留证据。
> 目的：验证租户路径从开通、登录、隔离、套餐、配额、到期到租户内授权是否真的走得通。
> 这条路径此前从没在界面上跑过：侧栏里的租户菜单是隐藏的，所有人都在租户 0。

## 0. 执行纪律（先读完再动手）

1. **只测不修**。发现问题只记录，不改代码、不改配置、不改数据库。
2. **遇到失败继续往下测**。一条用例失败不影响后续用例，除非后续用例依赖它（在结果里标 `BLOCKED` 并写明依赖哪条）。
3. **测试数据一律带前缀 `E2E-`（名称）或 `e2e`（编码、用户名）**，不要动已有数据。测完**不要删除**测试数据，在结果里记下创建了什么。
4. **不要做破坏性操作**：不点「删除租户」「清理租户数据」「同步菜单」「同步 API」，不改 admin 账号。
5. **结果只能是四种之一**：
   - `PASS`：实际结果符合「预期」
   - `FAIL`：不符合，附复现步骤
   - `BLOCKED`：前置条件不满足，没法执行
   - `OBSERVED`：用例本身只要求记录现象（标了「观察」的用例），照实描述，不判对错
6. **不要猜**。看不清、不确定的，就写「无法确认」并附截图，不要按预期填结果。

## 1. 证据要求

### 1.1 目录

所有证据放在仓库根目录 `test-evidence/tenant-e2e/<开始时间 YYYYMMDD-HHMM>/` 下（该目录已被 git 忽略）：

```
test-evidence/tenant-e2e/20261030-1000/
├── results.md          # 结果汇总表（模板见第 6 节）
├── data.md             # 本轮创建的测试数据清单（名称、编码、用户名、密码、ID）
└── screenshots/
    ├── TC-01-01-套餐列表.png
    ├── TC-05-03-network-403.png
    └── ...
```

### 1.2 截图规则

- 文件名：`<用例号>-<步骤号>-<简短描述>.png`，例如 `TC-09-04-配额超限提示.png`。
- **截整个浏览器窗口**，必须能看到地址栏 URL。能看到系统时间更好。
- 每条用例**至少两张**：操作后的界面，以及能证明结论的关键画面（提示文案、列表内容、按钮有无）。
- 涉及「接口被拒 / 返回什么」的步骤，**必须**打开浏览器开发者工具的 Network 面板，截图同时包含：请求 URL、方法、状态码、响应体（点开 Response 标签）。
- 页面出现报错、白屏、空列表时，**加截一张** Console 面板。
- `FAIL` 的用例要额外截出「出问题的那一步」的前一步，方便复现。

### 1.3 文字记录

`results.md` 里每条用例写：实际看到了什么（引用界面上的原文提示）、对应的截图文件名。
`FAIL` 和 `OBSERVED` 要写清楚：在哪个页面、点了什么、看到了什么、和预期差在哪里。

## 4. 测试用例

下文「平台」= 用平台管理员登录；「A 管」= 用租户 A 管理员登录（租户编码填 `e2ea`）；「B 管」同理。

---

### TC-01 建套餐（平台）

**步骤**
1. 打开套餐管理页，新增套餐 FULL、LIMITED（字段见第 3 节）。
2. 给套餐 FULL 新增配额：用户数上限 `USER_LIMIT = 3`；存储空间 `STORAGE = 102400`（单位是字节，即 100 KB）。
3. 重新打开两个套餐的编辑抽屉，检查模块白名单是否保存住。

**预期**：两个套餐都出现在列表里；配额列表显示两条配额；重新打开编辑抽屉时，模块白名单和保存时一致。

---

### TC-02 开通租户并创建管理员（平台）

**步骤**
1. 打开租户列表页，新增租户 A、B（字段见第 3 节，在同一个抽屉里填管理员账号）。
2. 在列表里找到两个租户，截图状态、套餐、到期时间这几列。
3. 打开「组织人员 → 用户管理」，看平台视角下能否看到 `e2ea_admin`、`e2eb_admin`，记录它们的用户 ID 到 `data.md`。

**预期**：两个租户都创建成功，状态为启用，套餐正确；平台能看到两个管理员账号。

---

### TC-03 登录页租户品牌

**步骤**
1. 退出登录，在登录页「租户编码」输入 `e2ea`，然后让输入框失去焦点。
2. 再输入一个不存在的编码 `e2ezzz`。

**预期**：输入 `e2ea` 后，登录框显示租户名 `E2E-租户A`；输入不存在的编码时不显示租户名，也不报错弹窗。

---

### TC-04 租户管理员登录与侧栏（A 管）

**步骤**
1. 租户编码 `e2ea`，用 `e2ea_admin` 登录。
2. 截图完整侧栏，并把所有一级、二级菜单展开后再截一张。
3. 依次点开侧栏里每个页面，记录哪些能正常打开、哪些报错或显示空白/403。

**预期**：能登录；侧栏能显示菜单（**侧栏为空、或者跳到错误页，都记为 FAIL**）；
套餐 FULL 包含全部模块，所以列出的页面都应该能打开。
平台专属页面不应出现，或者点开后被拒：租户管理、套餐管理、菜单管理、API 管理。如果出现了，记下来。

---

### TC-05 租户管理员的按钮权限（A 管）⚠ 高风险

**背景**：列表上的新增/编辑/删除按钮按权限编码显示。租户管理员角色是按模板生成的，
模板里可能没有这些编码。

**步骤**
1. 打开 用户管理、职位管理、组织架构 三个页面。
2. 截图每个页面的工具栏（有没有「新增」）和任意一行的操作列（有没有「编辑」「删除」）。

**预期**：租户管理员能看到并使用这三个页面的新增、编辑、删除按钮。
**任何一个按钮缺失都记为 FAIL**，并在结果里写清楚哪个页面缺了哪个按钮。

---

### TC-06 套餐模块白名单：侧栏与接口（B 管）

**步骤**
1. 租户编码 `e2eb`，用 `e2eb_admin` 登录，截图完整侧栏（全部展开）。
2. 记录侧栏中**不属于**仪表盘和组织人员的菜单项，例如站内消息、日志审计、系统管理。
3. 打开开发者工具 Network 面板，点开其中一个白名单外的页面（如 日志审计 → 登录日志），截取列表请求的状态码和响应体。
4. 再点开一个白名单内的页面（用户管理），确认能正常加载。

**预期**
- 白名单外页面的数据请求返回 **403**，页面不展示其他租户或平台的数据。
- 白名单内页面正常加载。
- 侧栏是否显示白名单外的菜单：**观察项**，照实记录。已知侧栏过滤只检查顶层菜单，可能会显示出来。

---

### TC-07 数据隔离：列表（A 管、B 管、平台）

**步骤**
1. A 管：新建组织单元 `E2E-A-部门`、职位 `E2E-A-职位`、用户 `e2ea_u1`（密码同上，挂到 `E2E-A-部门`）。
2. 退出，B 管登录：打开 用户管理、组织架构、职位管理，搜索 `E2E-A`、`e2ea`。
3. 退出，平台登录：同样搜索。

**预期**
- B 管搜不到任何 `E2E-A-*`、`e2ea*` 数据（列表为空，或只有 B 自己的数据）。
- 平台能看到 A 创建的数据。

---

### TC-08 数据隔离：按 ID 直接访问（B 管）

**步骤**
1. 从 `data.md` 取 `e2ea_u1` 的用户 ID（在平台视角的用户列表或详情页地址里取）。
2. B 管登录，地址栏直接打开 `http://localhost:15888/opm/users/detail/<e2ea_u1 的 ID>`。
3. 打开 Network 面板，截取用户详情请求的状态码和响应体。

**预期**：页面上看不到 `e2ea_u1` 的任何信息；接口返回 403/404 或空数据。**能看到 A 的用户信息即为 FAIL（严重）**。

---

### TC-09 跨租户登录

**步骤**
1. 租户编码 `e2eb`，用户名 `e2ea_admin`，正确密码，尝试登录。
2. 租户编码留空，用户名 `e2ea_admin`，尝试登录。
3. 租户编码 `e2ea`，用户名 `admin`（平台管理员），尝试登录。

**预期**：三次都登录失败，提示中不泄露「用户存在但租户不对」这类细节（照实记录提示原文）。

---

### TC-10 用户数配额（A 管）

**前置**：套餐 FULL 的 `USER_LIMIT = 3`。租户 A 已有 `e2ea_admin`、`e2ea_u1`，共 2 人。

**步骤**
1. A 管新建用户 `e2ea_u2`，应成功（第 3 人）。
2. 再新建用户 `e2ea_u3`。截取提示，以及 Network 面板里该请求的状态码和响应体。

**预期**：第 2 步被拒，提示和配额有关（响应里含 `USER_LIMIT` 或配额字样）；用户列表里没有 `e2ea_u3`。

---

### TC-11 存储配额（A 管）

**前置**：套餐 FULL 的 `STORAGE = 102400`（100 KB）。

**步骤**
1. 准备两个本地文件：一个约 50 KB，一个约 200 KB（任意内容）。
2. A 管打开 `http://localhost:15888/system/files`，上传 50 KB 的文件。
3. 再上传 200 KB 的文件，截取提示和 Network 面板。

**预期**：50 KB 上传成功；200 KB 被拒，提示和存储配额有关。

---

### TC-12 到期只读（READONLY）

**步骤**
1. 平台：把租户 A 的到期时间改成**昨天**，保存。
2. 退出，A 管登录（若登录被拒，记录提示原文，并把本用例记为 `FAIL`）。
3. 打开用户管理，确认列表能正常查看。
4. 尝试编辑 `e2ea_u1` 的姓名并保存，截取提示和 Network 面板（状态码、响应体）。
5. 退出，平台：把租户 A 的到期时间改回一年后。
6. 退出，A 管登录，再编辑一次 `e2ea_u1`，确认能保存。

**预期**：第 3 步能查看；第 4 步保存被拒（403）；第 6 步恢复后能正常保存。

---

### TC-13 租户停用（B）

**步骤**
1. 先在一个窗口用 B 管登录并停在用户管理页，**保持这个窗口不退出**。
2. 在另一个无痕窗口用平台账号登录，把租户 B 的状态改为**停用**。
3. 回到 B 管的窗口，刷新用户管理页，截取 Network 面板。
4. B 管退出后重新登录，记录提示原文。
5. 平台把租户 B 的状态改回**启用**；B 管再次登录，确认恢复正常。

**预期**：第 3 步请求被拒（401 或 403）；第 4 步无法登录；第 5 步恢复后能登录。

---

### TC-14 租户内角色与按钮（A 管 → 普通用户）

**步骤**
1. A 管打开角色管理，新建角色 `E2E-A-只读用户`，权限配置里**只勾**「用户管理 → 查看」，保存。
2. 截图这个角色的权限树，看页面和操作的层级是否清楚。权限树里是否出现平台专属的内容（租户、套餐、菜单管理、API 管理），记为观察项。
3. 把 `e2ea_u2` 的角色设为 `E2E-A-只读用户`（只给这一个角色）。
4. 退出，用 `e2ea_u2` 登录（租户编码 `e2ea`）。
5. 截取侧栏，以及用户管理页的工具栏、操作列。

**预期**
- 侧栏只有用户管理（及其所在目录、仪表盘这类公共页面），没有职位管理、组织架构、角色管理。
- 用户管理页**没有**新增、编辑、删除按钮，列表能正常查看。
- 地址栏直接打开 `http://localhost:15888/opm/positions`：页面数据请求被拒（截 Network 面板）。

---

### TC-15 审计日志隔离

**步骤**
1. A 管打开 日志审计 → 登录日志，截图。
2. 平台打开同一页面，截图。

**预期**：A 管只能看到租户 A 账号（`e2ea_*`）的登录记录，看不到 `admin`、`e2eb_admin` 的记录；平台能看到全部。

---

### TC-16 站内信隔离（可选）

**步骤**
1. 平台打开 站内消息 → 站内信，发送一条消息，标题 `E2E-给A`，接收人选 `e2ea_u1`。若界面上选不到租户用户，记 `BLOCKED` 并写明原因。
2. `e2ea_u1` 登录，查看顶栏通知和收件箱。
3. B 管登录，查看收件箱。

**预期**：`e2ea_u1` 收到这条消息；B 管看不到。

---

### TC-17 套餐不含仪表盘（观察）

**步骤**
1. 平台：编辑套餐 LIMITED，把模块白名单改成**只留**组织人员（OPM），去掉仪表盘。
2. B 管登录，截取登录后的页面、侧栏，以及 Network 面板里 `/admin/v1/routes` 和 `/admin/v1/perm-codes` 两个请求的状态码。
3. 平台：把套餐 LIMITED 的白名单改回仪表盘 + 组织人员。

**预期（观察项）**：照实记录登录后能否进入系统、侧栏是否为空、那两个请求的状态码。
**背景**：取菜单和取权限码的接口归在「仪表盘」模块，去掉仪表盘后，租户可能连菜单都拉不出来。

---

### TC-18 到期阻止登录（BLOCK_LOGIN，耗时，可选）

**说明**：BLOCK_LOGIN 由每小时整点的后台扫描执行，最长要等 1 小时。时间不够就记 `BLOCKED`，写明原因。

**步骤**
1. 平台：把套餐 LIMITED 的到期策略改为 BLOCK_LOGIN，把租户 B 的到期时间改为昨天。
2. 等到下一个整点过 2 分钟后，B 管登录，记录提示原文；平台查看租户 B 的状态。
3. 恢复：平台把租户 B 的状态改回启用、到期时间改回一年后，并把套餐 LIMITED 的策略改回 READONLY。

**预期**：整点后租户 B 的状态变为「已过期」，B 管无法登录；恢复后能登录。

## 5. 不在本轮范围（界面测不了，由代码测试覆盖，不要尝试）
